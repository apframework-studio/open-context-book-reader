# 图书分析与交接

## 用什么问题读

先问这本书要解决什么，作者凭什么、通过哪些部分完成目标。对每个主要部分记录「输入或前提 → 本部分新增什么 → 它怎样支撑后续部分」，再整理跨章依赖、重复、跳跃和张力。书若主要是教程，地图可以是学习路径；若主要是论证，地图突出前提、推理和反驳。

根据书的作用选择必要的检查项，不要求一本书适配所有项：

| 书的作用 | 重点辨认 |
| --- | --- |
| 科学解释/科普 | 研究问题、方法与样本、证据和机制的区别、确定性和适用范围 |
| AI/技术教程 | 概念依赖、算法或系统机制、可复现条件、版本与时间敏感结论 |
| 哲学/思想论证 | 概念定义、前提、推理方式、可能反例与未回答的反驳 |
| 实践方法/商业 | 建议所需条件、案例与普遍证据的区别、风险和失败模式 |
| 传记/思想史 | 时间线、史料来源、作者解释与事件事实的区别 |

## 输出形状

按材料量与用户目标缩放。只有书名或目录时止于「初步定位」；局部正文只写局部地图。可参考：

```markdown
# 书名：阅读地图（全书/局部/初步定位）

## 来源与覆盖
书名、作者、版次/文件标识、输入格式、实际阅读范围、缺漏和批注归属。

## 读前定位
所属领域与本书功能；核心问题；目标读者/先修知识；写作背景；相关作品及关系；为什么现在读（有读者目标时）。

## 阅读地图
核心问题或目标 → 主要框架 → 各部分的作用及相互关系 → 关键证据/推导/实例与假设 → 结论和边界。

## 精选笔记
| 原文位置 | 作者说了什么 | 我如何理解 | 我同意或质疑什么 | 还需查证什么 |
| --- | --- | --- | --- | --- |

## 综合判断与闭卷回想
可复述的主线、尚未解决的问题、3–5 个闭卷问题。
```

笔记表中的「我」仅在读者提供了其想法时代表读者。AI 生成的解释或质疑要标「理解建议」「质疑线索」，或将栏位留给读者填写。作者的结论、事实依据、案例、模型假设要分开；不把书外核查混写在原书观点里。引文简短且对应原文位置。

## 独立保存

用户需要文件时，保存 `analysis.md`；如需继续回查原文，同时保留 `source.md` 与 `manifest.json`。分析里记录来源 hash、版次、覆盖范围、原文位置和批注来源。
