# 格式与提取说明

## 最小工作流

```bash
python3 scripts/extract_book.py /path/to/book.epub --output /path/outside/skill/book-package
```

输出目录必须尚不存在，且位于 skill 仓库之外。脚本只读取输入，写 `source.md` 和 `manifest.json`。`source.md` 每个单元前有原文位置注释；`manifest.json` 记录源文件 SHA-256、元数据、警告、原文位置与归一化文件行号。源文件及大量原文不要提交到 skill 仓库。分析时可用 `source.md#L42`，同时保留原书定位。

需要 `beautifulsoup4` 处理 HTML/EPUB，`EbookLib` 处理 EPUB，`PyMuPDF` 处理 PDF；依赖见 `requirements.txt`。依赖缺失时，脚本会给出所需包。纯文本无需第三方包。

## 格式检查

| 输入 | 保留的位置 | 需特别核查 |
| --- | --- | --- |
| PDF | `p.N` 页码；批注页码 | 多栏阅读顺序、扫描页、页眉页脚、图表和公式；高亮矩形提取的文字仅为近似值 |
| EPUB | spine 阅读顺序中的文件名和已有锚点 | 导航页重复、脚注/图表、作者与版本；阅读器划线通常在独立导出文件中 |
| TXT/Markdown | 原文件 `L行号` | 编码、章节标题、缺页或格式丢失 |
| HTML | 有则保留祖先 `#id`，否则记元素序号 | 重复目录、异常嵌套、正文是否完整、远程图片未包含在文本中 |

文本提取的覆盖状态是机器层面的。`partial` 可由无文本 PDF 页触发；`extracted` 也要结合目录和实际内容判断是否为全书。图片警告代表相关内容尚未分析。扫描 PDF 应先使用用户提供的 OCR 文本或专门 OCR 流程，之后回查关键段落。

## 划线、批注与外部文本

- PDF 内嵌批注可得到类型、页码、批注作者字段、评论与高亮矩形附近的近似文字。作者字段可能是设备/账户名，不足以证明就是当前读者。
- EPUB 文件通常包含正文和导航；阅读器的划线与笔记常由平台单独保存。接受用户给的 Markdown、TXT、JSON 或粘贴文本作为伴随材料。先记录来源、导出工具、时间和字段含义，再与正文位置匹配；匹配不上时保留「位置待核」。
- 例如某些平台 JSON 将目录放在 `book.catalog_list`，笔记放在 `notes`，并有 `note_line`、`note`、`content`、`is_from_me` 等字段。`is_from_me=0` 不能被写成用户个人笔记；`note` 为空时，也不能把划线扩写成用户评论。字段语义不明时请保留原始归属描述。
- 上游已整理好的书籍文本若缺少版次或原始位置，记为「文本导出位置」，不要伪造 PDF 页码或 EPUB 锚点。

## 提取失败

若文件损坏、加密、仅有图片或乱码，停止基于该文件的全书结论；列出可读范围与所需补充材料。外部简介、目录和评论只能用于明确标记的初步定位。
